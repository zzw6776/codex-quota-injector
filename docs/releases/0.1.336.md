# 0.1.336

## 新增

- macOS 新增 Codex 后端管理，可在桌面内置版本、已安装的官方 Alpha 和自定义 CLI 路径之间选择；切换前会验证版本与 app-server 初始化，启动失败时自动回退到可用版本。
- 新增实验性 MCP 连接共享开关，仅对 Codex `0.166.0-alpha.1` 及以上兼容版本开放并单独验证，关闭时不会注入该实验配置。

## 修复

- 官方 Alpha 改为同时下载并校验 Codex CLI 与 `codex-code-mode-host`，避免仅安装 CLI 后代码工具因缺少宿主进程而无法启动；旧的不完整安装不会再被识别为可用版本。
- 自动回退仅在备用后端成功启动后才保存选择；备用后端也无法启动时会保留用户原来的 Alpha 或自定义后端设置。
- 自动回退成功后会结束临时回退状态，MCP 连接共享开关可继续正常切换并准确提示重启要求。
- 模型目录或中继准备失败而降级为官方模式时，会确认桌面实际启动的内置后端，同时保留用户选择的 Alpha 或自定义后端供下次重试，避免面板长期显示“尚未确认”或误报运行版本。
- 后端文件即使在原路径被桌面更新或手动替换，也会按文件身份识别为新运行时并重新验证；需要时会强制切换 app-server，避免继续复用旧进程。
- 修复凭据变化或手动刷新恰好遇到后台模型目录刷新时请求被吞掉的问题；旧凭据返回的结果不会再覆盖新账号目录。
- OAuth 官方模型目录改用 Codex 专用接口，并按账号、实际 CLI 版本及桌面请求身份隔离缓存，避免公共模型接口不兼容或切换后端后复用错误目录。
- 官方模型目录的内存状态与磁盘缓存使用相同的账号、CLI 版本和请求身份边界；新作用域刷新失败时不会残留上一版本或上一账号的目录。
- 手动刷新会绕过一小时的新鲜缓存并立即检查远端；启动和后台检查继续使用缓存及失败退避，避免无意义的频繁请求。
- 任务工具健康检查改为只在进入当前任务后按需验证；任务选择使用可撤销的最新状态快照，切换或离开任务会取消旧检查与重试并忽略迟到结果，重新进入时只复用已通过项，避免恢复历史任务时重复拉起多批 MCP 进程。

## 改进

- 官方 Alpha 下载仅接受 OpenAI GitHub Release 中匹配当前 Mac 架构的双组件，完成大小、SHA-256、Mach-O 架构、版本及 app-server 握手校验后再原子切换；下载或切换失败时保留原版本。
- 即使没有模型扩展，选择受管后端时也会通过 macOS shim 启动所选 app-server，确保后端选择和 MCP 共享设置实际进入桌面启动链路。
- Codex 桌面更新导致内置 CLI 版本变化后，会重新验证已选 Alpha 或自定义后端并在面板提示实际使用版本；验证失败时改用更新后的桌面内置 CLI，避免无提示继续使用不兼容后端。
- 切换后端时会按 MCP 共享开关的最终启动参数重新验证；修复同版本损坏安装成功后会清理已验证可替代的旧目录，避免隐藏备份持续占用磁盘。
- OAuth 官方模型目录改为按账号隔离缓存，并由统一协调器串行处理启动、定时、账号、凭据及手动刷新；正常情况下每小时检查一次，失败按退避策略重试。
- 已验证的后端选择会直接复用于启动与定时目录检查，不再因读取当前版本而反复启动临时 app-server 探测进程。
- 后端配置、已验证候选和实际运行版本改为分离管理；设置写入、启动回退和就绪确认按同一事务顺序处理，失败不会提前改变下一次启动选择。
