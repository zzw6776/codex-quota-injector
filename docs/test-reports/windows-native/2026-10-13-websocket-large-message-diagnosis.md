# 2026-10-13 Windows WebSocket 大消息断连排查

## 结论与范围

用户报告“适配最新游戏 UI (2)”聊天偶发没有延时，进一步要求排查 WebSocket 不稳定。当前证据高度指向历史图片使整轮请求过大，触发上游 WebSocket 消息大小限制；不是仅凭网络可达性推断原因。

本轮在同一个 Windows 原生网络、同一账号、相同人工输入下，绕过 Relay 直接连接官方端点和经过正在运行的正式 Relay，均复现 **22,442,143 字节消息被关闭，关闭码 1009**。小消息在两条路径均能得到参数校验回复。1009 的标准含义是消息过大，见 [RFC 6455 §7.4.1](https://www.rfc-editor.org/rfc/rfc6455.html#section-7.4.1)。尚未探测准确字节上限，不声称限制是 16MiB。

事故历史没有保存上游关闭码，因此没有把人工复现的 1009 冒充历史日志原文。这是大小对照及历史输入体积支持的高置信归因。不是同版本官方 app-server 发起的全历史重放，也不是完整后台/桌面验收，不将本报告自动套用到其他断连。

## 实际输入与环境

- 工作区：0.1.324，`ec830ec`；本轮未修改生产代码。
- 日常 Relay：正在运行的 Windows x64 正式 0.1.321，协议 97；相关 Router/采样代码与当前源码比较无差异。
- 官方 CLI：通过正在运行的上游进程精确可执行文件路径执行 `--version`，为 `0.162.0-alpha.17.2`。
- 诊断客户端：Windows 原生 Node `v22.23.2`，项目 Windows `node_modules` 的 `ws`；未混用 WSL 依赖。
- 代理：Mihomo TUN 开启，系统代理关闭；事故期间目标 `chatgpt.com:443` 的六次 Relay 连接均命中同一代理节点，没有误走 DIRECT。节点身份及账号不写入公开报告。

## 历史证据

时间为北京时间 2026-10-13：

1. 22:30:28 开始新回合，六次 WebSocket 连接尝试；22:30:44 至 22:31:23 出现五次重试，客户端只记录 `websocket closed by server before response.completed`。
2. 22:31:35 记录 `falling back to HTTP`；紧接着记录原始请求 **22,442,115 字节**，zstd 后 **16,413,584 字节**。
3. 22:31:36 HTTP 首次返回 502，22:31:50 重试后返回 200。502 的原始响应正文没有留存，不能单独归因。
4. 按本聊天 `forked_from_ordinal_exclusive=841` 追踪父聊天，取父聊天最近压缩后的继承历史及本聊天事故前新增项：四张大图片及一张压缩历史内的小图片，data URL 合计 **21,867,218 字节**，约为上述 HTTP 请求体的 **97.4%**。这个占比是历史图像编码与 HTTP 日志体积的对照，不冒充抓取的完整 WebSocket 帧。
5. 较早同类断连发生 HTTP 回退时，请求体曾达 79,080,101 字节；仅作旁证，没有再次重放该历史。

## 限时定向诊断结果

| 检查 | 原始结果 | 能说明什么 |
| --- | --- | --- |
| TUN + WebSocket 压缩 | 握手 101；4 次 pong；168–189ms；正常关闭 | 当前基本连接正常 |
| TUN + 不压缩 | 握手 101；4 次 pong；155–176ms；正常关闭 | 小消息未复现压缩兼容性问题 |
| 显式 HTTP CONNECT 代理 + 压缩 | 握手 101；4 次 pong；166–179ms；正常关闭 | 显式代理路径也能建立连接 |
| 官方端点空输入预热，无 Relay | `response.completed`，2 输入 Token、0 输出 Token | 空输入预热通过 |
| 当前正式 Relay 空输入预热 | `response.completed`，2 输入 Token、0 输出 Token | 正式 Relay 空输入预热通过 |
| 1,167 字节人工消息，无 Relay / 正式 Relay | 两者均返回 `Unsupported parameter: diagnostic_padding` | 小帧进入了应用参数校验；这是刻意使用的无生成对照，不能标为有效模型请求成功 |
| 22,442,143 字节人工消息，无 Relay / 正式 Relay | 两者均以 **1009** 关闭，没有参数校验回复 | 大消息在参数校验前被拒绝；移除 Relay 仍复现 |

人工大小对照使用同一份随机 base64 填充 `diagnostic_padding`，没有携带用户对话或图片；所有请求均 `generate:false`、`input:[]`。预热方式依据 [OpenAI WebSocket 文档](https://developers.openai.com/api/docs/guides/websocket-mode)。实际两个合法预热合计返回 4 输入 Token、0 输出 Token，不能宣称零 Token。非法字段对照未返回 usage 或模型输出。

小帧直连在参数错误后客户端主动 close，最终观察到 1006；正式 Relay 对应关闭为 1000。保留这一原始差异，不把它当成大帧 1009 的成因。没有执行真实生成、完整免费回归、后台/桌面验收或启停恢复。

## 后续处理边界

优先减少后续工具图片进入历史的体积，核对长历史重连时的大消息处理；不能靠重复发送同一个过大请求解决。Relay 当前保留有效上游关闭码，但官方客户端日志只显示泛化断连，且 Relay 的细节日志默认关闭；可独立改善脱敏关闭码和消息字节数记录。没有为上游限制增加项目绕过，没有改代理、删除历史、切换账号或重启应用。

私有原始材料保留在 `.runtime/ws-diagnosis-20261013/`：`incident-summary.json`、`probe-results.json`、`prewarm-results.json`、`size-1024-results.json`、`size-22442000-results.json` 以及诊断脚本。公开摘要不包含凭据、路由令牌、节点地址或图像内容。
