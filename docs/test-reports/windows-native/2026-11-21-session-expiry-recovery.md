# Windows Session 过期自动恢复定向验证

2026-11-21，Windows 原生 x64。工作区应用版本 `0.1.348`、Widget `210`、Relay `102`，基线提交 `857a45fab66340b4bb4ecbb79258e9f23f698606`，实际官方 CLI `0.171.0-alpha.13`，测试控制器使用 Node `v22.23.2`。本报告只覆盖 Session 过期后的账号恢复与官方登录，不替代完整免费回归、真实模型测试或 Windows 完整启停恢复验收。

## 结果

- 相关自动化契约 **28/28 通过**：覆盖当前 Session 续期、跳过失效备用账号、自动切换下一个已验证账号、无可用账号时调用官方 `codex login`、取消登录、凭据落盘门禁及安全重启等待。
- Windows 实机故障注入 **1/1 通过**：临时将两个真实账号隔离为不可切换状态，并以唯一伪 Session 触发永久失效。注入器确认无可用 Session 后停止桌面一次，启动官方浏览器登录；新凭据落盘并同步为有效账号后，才执行一次受控桌面启动。
- 测试结束后原有两个账号均已恢复，伪账号已清除；当前官方凭据与选中账号匹配。开发注入器 `0.1.348` 为 `ready`，CDP 端口可访问，页面实际存在 Widget `v210`，当前 Relay 实例存活。
- 登录后的项目控制日志只记录一次“正在以调试及模型中继模式重启 Codex”。账号列表恢复阶段复用已运行桌面，没有再次请求项目重启；其后出现过一次瞬时 CDP 断连，当前已自动恢复，不影响最终状态。

## 失败对照与根因

首轮实现仅清空 `auth.json` 后启动桌面，并以“发现桌面进程”作为成功判据。实机实际显示“未能加载账户信息”并退出，因此首轮报告已更正为失败。当前 Codex 二进制生成的 app-server Schema 与桌面包代码共同确认，官方登录必须显式调用 `account/login/start` 的 `chatgpt` 流程；本次最小实现改用同版本官方 CLI 的 `codex login` 浏览器流程，不再把无凭据启动等同于登录。
