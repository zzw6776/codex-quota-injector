# 测试报告归档

这里保存可随 Git 同步的脱敏报告摘要。完整 JSON、事件日志、截图和私有控制材料仍在执行机器的 `.runtime/`；摘要中的原始路径仅用于定位，不能当成已上传的证据链接。完整材料另有归档时，应记录其可访问链接与摘要。

## 保留规则

- 按测试组件、运行环境和架构分别保留最近 **5 次执行**，以执行时间排序；macOS、Windows 原生和 WSL 原生分别维护。一次执行的原始摘要、规则复核和接受项属于同一组，不重复计数。
- 最新有效通过报告、未解决问题的关键证据及被现有归因文档引用的报告额外保留，并注明保留原因。清理前先检查引用；不能删掉仍被引用的原始报告而仅留下通过复核。
- 每次获授权的测试结束后，归档对应组件的通过、失败或阻断结果，更新本页索引；归档本身不触发测试、模型请求、重启或自动推送。通过正常 Git 提交和推送完成跨机器同步。
- 保留原始执行时间、版本、源码摘要、实际运行环境和模型、通过数/总数、逐项状态、阻断原因以及原始文件 SHA-256。未记录的字段明确留空，关联报告推定的版本单列依据。新报告已有分文件输入清单、组件摘要和运行时摘要时一并保留；不得用当前源码清单补写旧报告。
- 原始执行状态与当前代码适用性分开保存。规则复核、接受上游或兼容性阻断必须另存，记录原始报告摘要、依据、接受项数量及是否重新执行；未执行不能改成通过。
- 只提取可分享字段，不复制凭据、账号标识、私有配置、请求正文、任务对话、本机绝对路径或控制器文件。日志、截图等大文件不纳入此目录。

首批归档现有 macOS 六类测试的最新记录及一份已有的规则复核；每组后续累积到最近 5 次。历史原始材料没有被清理。

## 复测与验收决策

先比较组件、原生环境的执行输入与实际运行时，只对确实受影响的组件或用例安排验证；未受影响的结果直接复用。版本号、报告和说明文档变化不触发行为复测。旧报告缺少清单时先做差异审核，审核结论与依据另存，不能仅因清单缺失就要求全量重跑。

最终验收允许计入已确认并登记接受的官方上游、环境兼容性及同类已知问题：原始 `executionStatus` 保留 `failed`、`blocked-upstream` 或 `not-executed` 等真实状态，另列 `acceptanceStatus: passed`，同时列出实际通过数、接受项及证据。不支持的能力另列不适用，不混入真实通过数。

后续命中同一已知问题且满足其证据复用条件时，直接引用已有归因并计入验收通过，不重复完整定位或自动重跑；症状、环境或相关链路变化时只核对必要差异。普通漏测、未确认问题和项目自身回归不能自动套用已知问题接受项。最终验收检查适用项是否已实际通过或已有明确接受依据，不能只因原始报告有阻断就判整批不通过，也不能在受影响项目仍未验证时宣称全部通过。
