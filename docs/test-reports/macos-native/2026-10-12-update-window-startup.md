# 更新窗口启动、端口隔离和即时反馈

- 日期：2026-10-12（America/Los_Angeles）；macOS 27.0.1 arm64，Node v26.7.0，浏览器 Chrome/155.0.8059.39。
- 源码：应用 0.1.309 / Widget 191 / Relay 97。
- 范围：更新窗口启动及按钮反馈的定向免费验证、隔离原生窗口；未下载正式安装包、未替换或重启日常应用、零真实模型请求。不是完整免费、模型桌面或启停恢复验收。

## 原始问题与证据

用户先报告点击长时间无反馈，之后出现“更新状态窗口未能启动”。首次根据暂无 Worker/登记记录推断启动失败并不充分，用户确认窗口会延迟出现后已修正判断。原生程序准备阶段观测约 1.2–3.3 秒，只能证明每次 dev 点击编译带来等待，不能据此解释更长的全部耗时。

本轮错误截图对应 Worker 日志实际为 `EADDRINUSE: address already in use 127.0.0.1:49230`。隔离验证也使用原有固定端口，与用户操作发生冲突；保留这次测试污染事实，不能归因网络或官方 Codex。测试进程已结束。旧实现还在状态服务登记后即返回，没有确认原生窗口内容已加载，入口也缺少即时等待反馈。

## 修复

- 更新服务默认绑定端口 0，由系统分配独立端口；登记探测严格核对本机 URL、Token 和任务 ID。
- 首次状态内容插入页面后发送就绪确认；启动调用等待该任务页面就绪，最长 30 秒，进程提前退出立即报告退出信息和日志路径。
- 点击立即显示“正在打开更新窗口…”，阻止重复点击；用请求 ID 匹配后台响应，普通额度刷新不会误清等待状态。
- macOS dev 启动时预编译窗口，源码及架构相同复用缓存；并发预编译/点击合并构建，失败不留下缓存。正式版继续使用打包资源。
- 原生窗口输出写入 Worker 日志；关闭时只清除属于当前任务的登记记录。
