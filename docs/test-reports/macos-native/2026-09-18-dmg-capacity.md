- 日期：2026-09-18；macOS 26.6.2 (25G83)、arm64。契约测试与 SEA 运行时 Node 22.23.1，构建脚本宿主 Node 26.7.0。
- 源码版本：0.1.286；仅打包行为改变，Widget 174、Relay 87 不变。
- 范围：免费公共契约的打包子集及 macOS arm64 正式包验证。零模型请求、零应用重启，不是完整免费、桌面或启停恢复验收。

## 原始失败与归因边界

[Build Packages，提交 42dcb94](https://github.com/zzw6776/codex-quota-injector/actions/runs/35342864720/job/105593038995) 在 arm64 应用编译、签名后，创建 DMG 时报告 `No space left on device`，同时指向镜像卷内 Worker 的复制目标。三个平台的契约测试、macOS x64、WSL Relay 和 Windows 安装包均通过；Release 被跳过。

旧命令在相同 macOS 版本的本机对照成功，未复现远端 ENOSPC。远端旧日志没有宿主剩余容量，无法证明是宿主耗尽还是镜像自动容量估算不足。保留原始失败，不计为已确认上游问题，也不宣称本地通过证明远端已恢复。

## 改动

- 不再依赖 `hdiutil -srcfolder` 的默认容量及源文件系统选择。按文件逻辑大小、4 KiB 块对齐及目录开销计算容量，额外保留至少 64 MiB 或 25% 的较大者；显式指定 HFS+，输出仍为 UDZO DMG。
- 不以稀疏/压缩源文件的已分配块数作为复制容量，不跟随符号链接。
- 创建前记录源大小、分配块大小、镜像容量，以及输出目录/临时目录的可用空间；失败后再次记录空间并原样抛错，不盲目重试或清理宿主目录。
- 创建后执行 `hdiutil verify`。应用内容、签名及安装流程不变。

这是针对自动容量估算依赖的加固方案；事故精确根因及远端恢复仍待新 CI 证据确认。相比仅重试或清理 runner，方案保留可诊断信息；不引入手工创建、挂载、复制、转换的多阶段生产打包流程。
