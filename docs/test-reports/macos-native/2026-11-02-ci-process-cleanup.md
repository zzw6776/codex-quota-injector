# 2026-11-02 统计进程测试清理顺序修复

## 原始 CI 结果

[Build Packages #41422566586](https://github.com/zzw6776/codex-quota-injector/actions/runs/41422566586) 对应提交 `ed64b4f` / 应用 0.1.342。macOS 的 Node 22.23.1 非 UI 契约为 **738 通过、1 失败、2 跳过**；失败发生在统计进程全量发现用例的 after hook，缓存临时文件 rename 返回 ENOENT。Ubuntu、Windows 测试及版本说明校验通过，打包和发布步骤跳过，尚未生成该次正式发布。

## 原因与修复

`useTempDir` 先注册目录删除钩子，测试随后才注册关闭统计子进程的钩子。after 按注册顺序执行，子进程可能在目录已被删除后继续落盘。先前 CI 通过不证明该竞争不存在。

本次仅将该文件中五个真实子进程用例的关闭钩子移到目录清理注册之前；初始化中途失败时保留可选清理。失败用例新增断言，确认关闭时数据目录仍存在、删除目录前统计子进程已经退出。没有放宽业务断言、吞掉落盘错误或修改生产代码。

## 本地验证

- 环境：macOS arm64，Node v26.7.0，最终版本 0.1.343 / Widget 209 / Relay 102。
- 增加清理顺序断言后，原实现定向 **0/1**，稳定复现目录被提前删除；修复后 `node --test test/token-usage-process.test.mjs` **7/7**，零失败、零跳过。
- 用例日志中的 ENOTDIR 是刻意创建 sessions 文件以验证失败恢复，不是修复后的失败。
- 审查确认五处关闭钩子均在 `useTempDir` 之前注册；模拟服务用例不依赖临时目录，不改其清理流程。
