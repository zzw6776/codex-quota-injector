## 问题与修复

旧管理器已有候选时直接打开缓存安装包，不重新检查 GitHub；窗口启动器也不区分原确认页与最新候选。因此旧的 0.1.295 候选可以持续显示，并在打开时复用旧确认页。本轮实际读取 GitHub Latest 为 0.1.312，包含三个平台安装包；不能把未发布的源码 0.1.316 当成远端版本。

打开额度面板发起后台检查。点击右下角版本入口时，等待已有后台请求完成，再发起本次检查；ETag 304 复用已确认内容，检查失败则显示错误并拒绝打开缓存安装包。最新发布不再适用于当前平台时清除旧候选。

没有更新时，灰色当前版本号也可点击，立即显示“正在检查更新…”并暂时禁用。仍没有可用更新则恢复当前版本、不显示错误、不打开窗口；发现更新则打开最新确认页。已有更新时显示绿色“当前版本 → 目标版本”。旧 UI 与侧栏使用同一入口逻辑。

确认窗口只在发布版本、安装包 ID、运行实例 PID 与当前版本均一致时复用；候选变化则关闭尚未执行的旧确认页，重新打开最新确认页。已执行的任务保持原目标；已成功、失败、终止的结果仍由用户手动关闭，新检查打开独立确认页。服务接受关闭后拒绝迟到的确认请求，旧窗口关闭也不会清除新窗口登记。
