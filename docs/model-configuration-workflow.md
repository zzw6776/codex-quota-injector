# 模型参数保存与检测

从 0.1.255 起，模型管理将配置保存与真实能力检测拆开。

- **保存配置**只做本地校验和持久化，不读取远端模型列表、不执行能力检测、不自动重启。新配置标记为等待重启生效。
- **读取最新模型**只读取供应商模型列表，不发送推理请求。
- 每个模型单独提供**检测（消耗 Token）**。按钮仅在平台设置内提供，外层显示模型名称、状态和已检测配置的具体参数；成功结果填入表单，仍需点击保存才用于运行配置。不会连带检测同平台其他模型。
- 可跳过检测，在模型下展开**手动配置参数**，设置接口、推理历史、工具转换、图片、推理强度、并行工具和内置联网；上下文仍按 K 输入。手动参数标记为“手动配置”，不会伪装成检测通过，B2 的已检测配置门禁保持不变。
- 检测失败记录绑定 API 地址、Key 和模型 ID，持久保存最近结果。平台列表中的对应模型显示“检测失败”，具体原因进入设置查看；取消编辑或重启管理器不会将失败记录隐藏。成功检测本身不会把表单配置自动写入运行配置。
- 悬浮框收起后保留当前页面、模型编辑草稿和滚动位置；再次打开复用面板。拖动尺寸仍不持久保存。

## 超时与不支持的区别

单个检测请求默认超时从 30 秒提高到 90 秒。网络故障、超时、限流和暂时性服务错误最多尝试 3 次，重试间隔为 0.5 秒、1 秒，进度显示当前重试次数。认证和明确的参数拒绝不进行这种网络重试；工具结果不完整的原有协议重试保留，但不会再次放大已经耗尽的网络重试。

图片等可选能力连续失败后记为“暂不可用”，保留失败原因并限制该能力，其他检测和保存可以继续。只有明确不兼容的响应或图片内容校验失败，才能记为已确认“不支持”；不能把 HTTP 200 本身作为支持图片的证据。基础连接、工具续接或必要的 Codex 兼容验收失败仍标为检测失败，但用户可以自行手动配置后保存。

检测报告只记录模型、阶段、时间、结果和错误原因，不保存探测请求正文或 Key；运行参数只有显式保存才更新。新增检测结果通过请求 ID 回填对应草稿，进度更新不重绘整个 Widget。新平台首次保存后同步服务器分配的 ID，后续保存继续编辑同一平台。

## 0.1.258：图片预算和否定证据

Chat 和 Responses 图片请求统一限制为 256 输出 Token，保留原有推理设置，不在图片探针内部自动关闭推理。文本和工具续接的预算不变。

- 只有完整的最终答案正确匹配图片内容才能标记支持；推理文本不作为正确答案。
- 最终答案或无最终答案时的推理明确表示无法读取图片，连续两次验证一致后，将当前图片链路标记为不支持。预算耗尽不会覆盖这种重复否定证据。假设性的“如果无法读图”不作为明确否定证据。
- 仅预算耗尽或没有完整最终答案，记为检测未完成，不扩大预算重试、不误判为答错。其他能力检测及保存继续。
- Responses 图片不可用后，若 Chat 补测预算耗尽或暂时失败，整体图片状态保留为未完成，不能继承 Responses 的“不支持”结论。

实测官方 deepseek-v4-pro Chat 图片请求在 256 Token 下 7.648 秒返回，finish_reason=length，最终答案为空，256 Token 均用于推理并明确提到无法读图；原始无预算请求 90 秒超时，1024 Token 对照约 23.7 秒。以上为改动前直接请求的诊断证据，不代表改动后全流程已验收。

应用版本升为 0.1.258，检测缓存契约升为 15，因旧结果可能混用推理与最终答案或把预算耗尽当作答错，旧缓存显示“检测规则已更新”，不会自动付费重新检测。本次未改 Widget/Relay 协议或持久化结构。新增回归用例，完成语法与差异静态检查，未运行 A/B/C 或额外付费请求。检测后端不支持现有页面热加载路径，待下一次用户重启后加载，未主动重启。


## 0.1.259：检测与页面导航分离

模型草稿按平台保留。左上角返回只退出当前页面；检测完成后，无论停留在模型列表、首页还是另一平台设置，都回填发起检测的平台草稿。回填仅更新检测所得能力、推理强度和默认推理档位，保留上下文、模型选择等用户输入。再次进入后显示检测结果及“未保存”，显式保存后才更新运行配置并移除提示。取消编辑仍丢弃当前平台草稿。

检测中允许进入设置查看，参数编辑和重复检测保持禁用。检测阶段、进度和重试信息直接显示在对应模型检测按钮下方，页面底部不再重复展示检测进度。保存回执同样绑定提交的草稿，不修改此时正在查看的其他平台。

新增回归用例覆盖检测中退出与重新进入、离开页面后通过完整数据更新回填、不同平台同名模型的隔离、重新进入后保存仍为 verified，以及进度位置。本次未运行自动测试或付费请求；仅做语法、diff 静态检查和页面热加载核对。Widget 163；Relay 与检测缓存版本未变。

读取表单或修改模型名称、上下文等字段，不会自动将能力来源改为手动配置。手动修改能力参数时才切换来源；未检测模型直接保存时使用表单默认参数并标记手动配置。


## 0.1.261：图片检测未完成时继续验证备用协议

Responses 图片没有验证成功（不支持或检测未完成）时，均继续验证 Chat 图片链路。Chat 必须先通过工具续接、流式响应、并行工具检查和 Codex 组合兼容验收，再发送图片探针；最终答案正确才启用 Chat 图片路由，文本默认协议仍保持 Responses。该逻辑按检测结果工作，不按 K3 或供应商名称分支。

两个协议都未成功且至少一个仍未完成时，保留图片检测未完成，不能因另一个协议拒绝而判整体不支持。图片预算仍为每次 256 Token，同一协议预算耗尽不扩大预算重试；切换协议是验证另一条链路。网络故障的有限重试保持不变。

本机 K3 直连诊断：Responses 14.294 秒返回 HTTP 200、status=completed，但 output 只有 reasoning，没有最终答案；Chat 同一张图片在 7.717 秒正确回答，使用 71 输出 Token。这是原检测遗漏 Chat 补测的复现证据，不等同于改动后完整能力验收。

新增回归用例覆盖只有推理/预算耗尽后启用 Chat、Chat 兼容验收失败不能启用、未完成与不支持的合并，并调整有限重试的两协议请求数量断言。此改动只调整检测编排，沿用检测缓存契约 15、Widget 和 Relay 协议版本。应用版本 0.1.261；仅做语法和 diff 检查，未运行自动测试、付费复测或重启。检测后端需下一次重启加载，已有未完成结果需用户重新点击检测。

## 0.1.262：多个模型同时检测

模型检测不设数量或请求并发上限，不排队等待其他模型完成。注入器独立启动每个检测动作，后台和页面按平台、模型及请求 ID 保存进度与结果。同一模型再次发起检测时，旧请求可自然结束，但其进度和结果不能覆盖新请求。单个模型内存在依赖的工具续接步骤保持原顺序。

检测期间可继续编辑和保存其他参数。结果只回填对应的草稿；修改 API 地址、Key、模型 ID 或该模型的手动能力参数，以及删除/取消草稿后，旧结果不再回填。显示名称、上下文和选中状态在回填时保留。多个结果在同一次页面更新到达时全部处理，不使用单个全局结果槽。

只有本地设置写入顺序合并：保存、删除和检测报告提交都基于前一次落盘后的最新配置，避免并发完成丢失报告或撤销用户保存。检测请求本身不受此写入顺序限制。保存确认按当时发送的模型快照清除“未保存”，不会将保存之后才到达的检测结果误标为已保存。

新增后端回归用例覆盖三个检测同时启动、进度隔离、同时保存与乱序完成、旧请求迟到；浏览器用例覆盖同时点击多个模型、独立进度、手动参数保护和保存确认竞争。本次仅执行语法与差异静态检查，未运行自动测试或付费请求。

应用版本 0.1.262、Widget 165；本次检测编排不改变能力结论、Relay 请求协议或持久化字段，检测缓存/Relay/设置结构版本不因并发编排再次升级。后端调度和页面状态契约同时改变，不能只热加载页面，需下次重启统一加载；未主动重启。


## 0.1.264：检测诊断留证

每轮模型检测以 requestId 关联平台、模型和检测规则版本；每次实际请求以 sequence 关联开始、响应头、结束和重试事件。日志立即写入系统日志目录中的 injector.log，不等整轮检测结束。macOS 路径为 ~/Library/Logs/Codex Quota Injector/injector.log。

请求日志记录阶段、协议、是否流式、输出预算、推理参数、尝试次数、响应头耗时、总耗时、HTTP 状态和上游请求 ID。连接失败、等待正文失败和供应商错误分别记录；收到 HTTP 200 后正文超时仍保留实际状态。响应摘要包括终止原因、Token 用量、最终答案/推理长度及最多 512 字符摘要、输出结构和解析器识别到的答案长度。摘要先移除当前 Key 和图片 data URL 再截断，不记录请求正文、图片数据或完整响应；诊断回调异常不改变检测结果。

每次图片判定记录预期颜色序列、判定和原因；每轮最终报告另存 image 状态、支持标记、所选图片协议和原因，同时保存 requestId、请求数和规则版本。整体检测完成不等于图片通过。详细请求事件保存在日志，设置文件只保留各模型最新报告，重启后仍能回溯其检测编号。旧日志无法补回当时未记录的响应。

新增回归用例覆盖只有推理的图片响应、备用协议成功、正文超时重试、凭据跨摘要截断边界的脱敏、诊断回调失败，以及重载后图片未完成结论的保留。仅执行语法和 diff 静态检查，未运行自动测试或付费请求。

应用版本 0.1.264，模型设置结构 16；Widget 166、Relay 79 和检测缓存契约 15 不变。本次不改变能力判断规则。检测后端不能通过页面热加载替换，需下一次正常重启加载；未主动重启客户端。
