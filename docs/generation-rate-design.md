# 输出速率重新设计

状态：设计完成，尚未实施。2026-11-02 核对当前采集、计账、缓存及展示代码。

## 目标与指标口径

保留 Token、费用和首字延迟的现有含义，解决缓冲响应被显示为数万 tok/s 的问题。速率定义为“客户端观测到的估算输出吞吐量”，不声称是服务端逐 Token 生成速度。

当前协议只有响应级 usage，没有每个接收批次的精确 Token 数和服务端生成时间戳。因此单靠客户端计时无法还原真实 TPOT；更长的观察窗口也不能证明中间没有缓冲。

估算值使用完整响应的非推理输出 Token 数，除以可测输出阶段的时间并集。界面明确显示“估算速率”。取消把首批固定视为一个 Token 的 `output_tokens - reasoning_tokens - 1` 假设；不按字符数估算 Token，也不把响应 Token 分摊给多个输出阶段。

## 已确认的问题

- HTTP 在同一次 `data` 回调中拆出多条 SSE，再逐条调用时钟。解析、回调和事件循环开销会形成假的输出时间差。
- HTTP、原生 WebSocket、HTTP→WebSocket 桥接均进入同一观察器，但批次到达信息尚未传入观察器。
- 仅要求两个 delta 和正时长不能识别同批输出。现有 500ms 门槛可以过滤已报告的 1ms 样本，但属于精度门槛，不是缓冲检测。
- 首批增量可能包含多个 Token，固定减去一个 Token 无法严格匹配计时区间。

## 责任与数据流

| 层 | 负责内容 | 复用位置 |
| --- | --- | --- |
| 传输 | 在收到一批数据时采集一次时间和批次编号，解析前完成 | `response-stream.mjs`、HTTP 观察入口、WebSocket 接收入口 |
| 观察 | 按输出项记录首末到达、独立到达次数和覆盖完整性 | `response-observation.mjs` |
| 计算 | 验证可观测性、计算区间并集、生成估算结果或不可用原因 | `generation-speed.mjs` |
| 计账 | 按 response ID 配对 usage，只汇总有效样本 | `token-usage/generation.mjs` |
| 展示 | 展示估算值、覆盖情况和不可用原因，不重新推导速率 | Widget 用量与请求明细 |

不新建采集服务、常驻进程、采样定时器或独立测速缓存。

## 采集规则

1. HTTP 每次解码后数据到达时，在解析 JSON/SSE 前取一次时间。同次到达解析出的全部事件共用该时间和批次编号；残余 SSE 拼接到完整时归入使其完整的到达批次。
2. 原生 WebSocket 在 `message` 回调入口、解析前取时间；HTTP→WebSocket 桥接使用上游 HTTP 到达信息，不能以本地重新发送消息的时间计速。
   `transport-diagnostics.mjs`、`turn-state-monitor.mjs` 等观察器包装层必须原样透传接收元数据，不能在包装层重新取时间或丢弃批次。
3. 耗时使用单调时钟，并在请求开始时建立时间原点；持久化日期继续使用现有墙钟。不同计时原点的数据不得相减。
4. 观察器每个输出项只保留首末批次、首末相对时间和独立到达次数；不保留批次列表、正文或原始数据块。
5. 同批多个 delta 只算一次到达。重复完成事件、工具执行结果和响应收尾事件不延长输出阶段。

## 可用性与计算

- usage 必须能通过 response ID 与完整输出样本配对；非推理输出 Token 必须大于零。
- 每个纳入请求的输出项都必须有至少两次不同时间的独立到达。单批、只有最终正文、缺少输出阶段或观察中断均不可计算；不能只取完整请求中剩下的可测部分。
- 完整输出阶段的时间并集至少 500ms。该常量只抑制短窗口误差，不表示模型速度准确，也不增加最大速率截断。
- 并行输出重叠只计一次；推理、两段输出之间的空白、工具执行和等待不计入分母。文字和工具参数均计入非推理输出。
- 回合速率等于有效请求的非推理输出 Token 总和除以相应输出时长总和；不平均各请求的 tok/s，不把无效请求的 Token 加入分子。
- 单个输出项独占整个响应时可以展示该项估算速率；多项响应只展示请求汇总，保持现有不摊派原则。

这能消除本地解析制造的时间差并拒绝缺乏采样依据的数据；上游多次分批缓冲仍可能影响估算值，不能通过增加几个阈值消除。

## 展示与历史

- 外层和请求明细统一使用“估算速率”，保留现有按需展开和会话 DOM 缓存。
- 无有效样本时隐藏外层速率，明细说明“输出一次性到达”“采样时间不足”或“缺少接收时序”。有部分有效请求时，明细显示有效请求数/已配对请求数，避免把局部样本理解为整轮全部输出。
- 新采集协议带有接收时序来源版本。历史样本没有批次证据，保留 Token、费用、首字及工具明细，旧速率标记为缺少接收时序；不靠旧事件重新拼造批次。
- 缓存迁移只处理工作集保留的速率字段，继续复用历史摘要索引。不扫描所有历史 rollout，不恢复旧会话 MCP，不额外发送模型请求。
- 实施时同步调整生成指标协议、Relay 协议、速率缓存兼容版本和 Widget 版本。不能把纯价格更新误当成需要重启 Relay；具体版本以实施时工作区为准。

## 验收

使用可控数据流覆盖以下失效机制，不依赖付费模型提供稳定分包：

1. 同一个 HTTP 到达批次包含多个 SSE delta，注入较长解析/回调开销，仍不能得到正的单批输出窗口。
2. 相同事件经 HTTP、WebSocket 及 HTTP→WebSocket 桥接，接收时序等价时结论一致。
3. SSE 跨块、压缩解码、单次返回完整正文和同批完成事件保持批次语义；不把解析时间计入生成时间。
4. 真实多批输出可计算；499ms 不可计算，500ms 可估算；较快但有效的流不被人为限速。
5. 文字/工具混合、并行输出、较长工具执行及重复终态不重复计账或拉长输出窗口。
6. 首批含多个 Token 时不再声称精确 TPOT；结果统一按已声明的估算口径计算。
7. 旧缓存迁移仅失效旧速率；Token、费用、首字、去重状态、历史摘要索引及会话切换显示保持一致。
8. 请求详情按需渲染，观察器状态不随 delta 数量增长，不引入新的常驻进程。

真实桌面只需确认新协议来源、估算标签与不可用原因传递正确，不能用“数值看起来正常”作为测速精度证明。
